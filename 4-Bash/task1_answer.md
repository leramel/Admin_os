# Скриптуем по полной
### 1. Что такое shebang?
Shebang — это специальная последовательность символов #! в самой первой строке скрипта, которая указывает операционной системе, какой интерпретатор использовать для выполнения этого файла.
```shell
#!/bin/bash
```
При запуске скрипта командой ./myscript.sh, ядро Linux читает первую строку, видит #!/bin/bash и понимает, что этот файл нужно передать интерпретатору /bin/bash.
Без shebang система попытается выполнить файл через текущую оболочку пользователя (что может привести к ошибкам,например, если sh вместо bash).
Другие примеры shebang:
```shell
#!/usr/bin/env python3 — для питон-скриптов
#!/bin/sh — для POSIX-совместимых скриптов
#!/usr/bin/perl — для Perl
```
### 2. Обязательно ли исполняемый файл должен иметь расширение .sh?
Нет, не обязательно. В Linux расширение файла не имеет значения для его выполнения. Система определяет тип файла по:
* Shebang в первой строке
* Биту исполняемости (chmod +x)

### 3. Напишите скрипт, который автоматически выполняет основные действия из блока «Работа с файлами». 
### 3.1) Скрипт должен использовать set -euo pipefail. 3.2) Объясните назначение каждого из этих параметров. 
### 3.3) Каталог для работы должен передаваться первым аргументом скрипта. 3.4) Если аргумент не передан — скрипт должен завершаться с понятной ошибкой и ненулевым кодом возврата. 
### 3.5) Повторный запуск скрипта не должен уничтожать уже существующие данные без предупреждения. 3.6) Основные действия скрипта должны записываться в лог-файл.

set -euo pipefail - Эта строка делает скрипт надёжным и безопасным
* -e - Если любая команда завершится с ошибкой (код ≠ 0), скрипт немедленно остановится. Без этого флага скрипт продолжит выполняться даже после ошибки.
* -u - Если скрипт попытается использовать неопределённую переменную, он завершится с ошибкой. Без этого флага пустые переменные просто превращаются в пустую строку, что приводит к тихим багам.
* -o pipefail - В конвейере (cmd1 | cmd2 | cmd3) код возврата — это код последней команды. С этим флагом код возврата конвейера = код первой упавшей команды.
  То есть если cmd1 упала, а cmd2 отработала — скрипт всё равно остановится.
